# Benchmarks (leg level, synthetic data)

Reproduce: `cd backend && python benchmarks/run_benchmarks.py --queries 4` (CSV in `benchmarks/results/`).
Setup: single machine, 4 random OD pairs per scale (seed fixed), max 2 stops (3 for D-3stop), departure windows of
2-4 days, 5 objectives. Recall = fraction of the exact Pareto vectors recovered; HV = Monte-Carlo hypervolume
relative to the exact front. Only 4 queries/scale: read as indicative, not statistically tight.

## What this does and does not show
* **Exact front vs. heuristics:** the weighted-sum sweep and a coarse ε-grid recover only ~40-80 % of the true
  Pareto itineraries and the gap widens with network size. Single-score ranking hides most good trade-offs.
* **Speed vs. generic solvers:** specialised label-setting is roughly 70-100x faster than repeated MILP solves (M, L)
  *for the same front*, and exact where the ε-grid is not.
* **Honest negative result:** brute-force DFS is *faster* than label-setting on S, M and even D-3stop. With a
  8-hour layover cap and ≤3 stops, the number of feasible paths stays small, so dominance bookkeeping is overhead.
  The DP advantage only appears when path count grows exponentially while label count stays polynomial
  (longer layover windows, more stops, dense multi-carrier schedules). An adversarial scaling experiment
  (stops 2→5, layover cap 8→24 h) is the next benchmark to run.
* The synthetic data is generated by us; real schedules have different structure (banked hub waves, fare buckets).
